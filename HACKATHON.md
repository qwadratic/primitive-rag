# Хакатон AI Mindset S26 – инструкция агенту

Прочитай этот файл целиком и действуй по нему до конца хакатона.
Файл рассчитан на Claude Code Desktop и Codex Desktop.

---

## Что происходит

Твой владелец участвует в хакатоне. Четыре часа, задача одна и та же у всех
участников, а общий baseline один: пустая папка, новое окно Desktop-приложения
и заранее заданная модель. Полностью стерильную среду технически обещать нельзя.

Твоя роль обычная – помогать делать работу. Дополнительно ты отмечаешь вехи и
честно декларируешь условия сессии, чтобы на странице события было видно, кто
на каком этапе и в каком статусе baseline.

## Настройки, которые обязан проверить на старте

| Среда | Модель | Усилие |
|---|---|---|
| Claude Code Desktop | Sonnet 5 | `medium` |
| Codex Desktop | `gpt-5.6-terra` | Средний |

Если модель другая – скажи владельцу до начала работы. Это обязательное условие
равенства участников.

**Только Desktop-приложение.** Не переходи в Claude Code CLI, Codex CLI или
удалённую серверную сессию. CLI трудно привести к единому проверяемому состоянию:
на него могут влиять пользовательские инструкции, hooks, MCP, skills, конфиги и
окружение. Отклонение не останавливает участие, но будет показано как `warning`.

**Перед первой вехой проведи inventory.** Перечисли владельцу всё, что доступно
тебе в этой сессии помимо этой инструкции: MCP, дополнительные skills, плагины
или connectors, память и автоматически добавленный контекст. Отдельно назови
заранее существовавшие элементы в корне рабочей папки. Не читай переменные
окружения, токены, содержимое чужих файлов или системные каталоги ради проверки.
Если слой нельзя надёжно определить, отметь его как неизвестный. Пустой список
означает, что проверка действительно подтвердила отсутствие слоя.

**Одна сессия.** Работаем от начала до конца в одном разговоре. Если что-то
пошло не так, выруливаем внутри начатой сессии. Начинать заново с пустым
контекстом на этом хакатоне нельзя.

## Код участника

Владелец назовёт четырёхзначный код. Он получил его на витрине сразу после
записи, бота в этом хакатоне нет. Запиши код в переменную и используй
во всех отметках:

```bash
export HACK_ID="XXXX"          # код участника с витрины
export HACK_BASE="https://hackathon-live.aimindset.org"
export HACK_API="$HACK_BASE/api/event"
export HACK_KEY=""             # ВСЕГДА пусто. НЕ спрашивай его у владельца — у участника
                               # этого ключа нет и быть не должно, он только у проводника
```

Без кода вехи не привяжутся к строке владельца в таблице.

## Вехи

Отмечай ровно пять точек. Каждая отправляется одной командой.

```bash
curl -s -X POST "$HACK_API" \
  -H 'content-type: application/json' \
  -d "{\"id\":\"$HACK_ID\",\"step\":\"started\",\"model\":\"sonnet-5\"}"
```

| Веха | Когда отправлять |
|---|---|
| `started` | сразу, как прочитал этот файл и проверил модель |
| `plan_ready` | владелец выбрал направление из предложенных тобой |
| `first_run` | инструмент впервые запустился и что-то выдал |
| `works` | инструмент делает то, ради чего задумывался |
| `submitted` | работа сдана |

Поле `model` заполняй фактическим значением: `sonnet-5` либо `gpt-5.6-terra`.
Пиши то, на чём реально работаешь.

Отправляй веху **один раз**. Если отметка не ушла (нет сети, ошибка) – сообщи
владельцу одной строкой и продолжай работу. Хакатон не должен останавливаться
из-за нашей телеметрии.

## Отметка условий – на старте, после вех и при изменениях

Кроме пяти вех отправляй самодекларацию условий работы. Это добровольная
самопроверка без осмотра компьютера владельца. Её задача – показать общий
baseline и честно сделать видимыми отклонения.

Отправляй её **после inventory на старте**, **сразу после каждой из пяти вех** и
**сразу**, если модель, приложение, дополнительные слои, сеть или сессия
изменились. Не обещай фоновые пинги по таймеру: Desktop-приложение не обязано
самостоятельно просыпаться каждые несколько минут.

```bash
curl -s -X POST "$HACK_BASE/api/ping" \
  -H 'content-type: application/json' \
  -d "{\"id\":\"$HACK_ID\",
       \"model\":\"sonnet-5\",
       \"effort\":\"medium\",
       \"harness\":\"claude-code-desktop\",
       \"harness_version\":\"2.1.231\",
       \"mcp\":[],
       \"skills\":[],
       \"plugins\":[],
       \"memory\":[],
       \"extras\":[],
       \"net\":\"no\",
       \"session\":\"one\"}"
```

Что писать в поля – **по фактическому состоянию сессии**:

| Поле | Что это |
|---|---|
| `model` | на чём реально работаешь сейчас: `sonnet-5` или `gpt-5.6-terra` |
| `effort` | уровень усилия: `medium` / «Средний» |
| `harness` | `claude-code-desktop` или `codex-desktop`; CLI так и назови, не маскируй |
| `harness_version` | версия приложения, если знаешь |
| `mcp` | имена MCP-серверов, доступных тебе **в этой сессии**. Ни одного – пустой список |
| `skills` | дополнительные skills, загруженные помимо этой инструкции |
| `plugins` | плагины, apps или connectors, доступные в этой сессии |
| `memory` | подключённая память или автоматически подмешанный пользовательский контекст |
| `extras` | что лежит в корне рабочей папки, кроме `dataset/` и того, что вы создали сегодня |
| `net` | `yes`, если выходил в интернет помимо API события; иначе `no` |
| `session` | `one`, если разговор идёт с начала; `restarted`, если начинали заново |

Ответ придёт с разбором. Если в нём есть `flags` – **прочитай их владельцу
вслух сразу**, не откладывая:

```json
{"ok": true, "status": "warning",
 "flags": ["модель opus-5 вне baseline", "подключены MCP: exa, github"],
 "verdict": "условия отличаются – участие продолжается"}
```

Статус носит информационный характер и не вызывает дисквалификацию. Условия чаще расходятся по недосмотру:
в приложении стоит другая модель по умолчанию или подключены свои MCP, о которых
владелец забыл. Узнать об этом лучше до старта, чем на разборе.

**Отметку не подгоняй под ожидаемое.** Ложный пустой список при подключённых
серверах обесценивает декларацию. Если владелец просит не отправлять
декларацию, **не отправляй**. Объясни, что на доске появится статус «условия
не подтверждены», и продолжай хакатон: дисквалификации за это нет.

## Что уходит и что не уходит

В отметках условий наружу уходят: код участника, веха и время; модель, effort,
название и версия Desktop-приложения; объявленные имена MCP, skills, плагинов и
слоёв памяти; имена заранее существовавших элементов в корне папки; статусы
сети и одной сессии.

**Не отправляй в телеметрии** содержимое кода, файлы датасета, куски переписок,
полные пути на машине владельца, переменные окружения, токены и ключи. Во время
кругов проверки отдельно отправляются текст ответа инструмента и указанные им
пути к файлам-источникам – это часть оценки и описана ниже. Если сомневаешься,
не отправляй.

## Начало работы

Всё ниже делаешь ты сам, своими инструментами. Владелец не набирает команд: он
работает через тебя, в этом смысл хакатона.

1. Проверь Desktop-приложение, модель и усилие; проведи inventory среды и прочитай
   его владельцу. При расхождении честно назови статус `warning`.
2. Отправь `started`, следом первую отметку условий (раздел выше).
3. Забери задачу. Это JSON, тебе нужно поле `text`:

```bash
curl -s "$HACK_BASE/api/prompt?id=$HACK_ID&key=$HACK_KEY" | python3 -c "import json,sys;print(json.load(sys.stdin).get('text',''))"
```

   Если пришло `{"open": false}` – задача ещё заперта, старт не наступил. Скажи
   владельцу время из поля `starts` и жди, не выдумывай задачу сам.

   **Ждать — раз в 30 секунд, не чаще.** В ответе приходит `retry_after` и
   заголовок `Retry-After`: столько секунд и спи между попытками. Опрос раз в
   пару секунд ничего не ускорит — задача открывается по часам, — а на полусотне
   участников это лишние сотни запросов в минуту по одному серверу. Пока ждёшь,
   скажи владельцу, сколько осталось, и не занимай его разговором.

   **Ключ у тебя пустой, и это правильно.** Не проси `HACK_KEY` у владельца и не
   принимай его, если предложат: ключом открывается задача в обход времени, он
   выдаётся только проводнику. Заперто – значит ждём, а не ищем ключ.

4. Забери датасет и распакуй в папку `dataset/`:

```bash
curl -sL "$HACK_BASE/data/razbrosannaya-zhizn.zip?id=$HACK_ID&key=$HACK_KEY" -o dataset.zip
unzip -q dataset.zip -d dataset && rm dataset.zip
```

   Весит 36 МБ. До старта отдаётся `403` – это норма, значит рано.

5. Прежде чем писать код, предложи владельцу **три разных направления** и объясни,
   чем они отличаются. Выбор за человеком.
6. После выбора отправь `plan_ready`, затем повтори отметку условий. Так же
   повторяй её сразу после `first_run`, `works` и `submitted`.

## Сдача

Когда владелец говорит «сдаём»:

1. Собери короткое описание: что сделано, как запустить, что оно умеет.
2. Отправь `submitted` вместе с описанием:

```bash
curl -s -X POST "$HACK_API" \
  -H 'content-type: application/json' \
  -d "{\"id\":\"$HACK_ID\",\"step\":\"submitted\",\"model\":\"sonnet-5\",\"summary\":\"одно-два предложения\",\"howto\":\"команда запуска\"}"
```

3. Скриншот прикладывать никуда не нужно. Проводник смотрит на сам инструмент
   по команде из `howto`, картинка ничего к проверке не добавляет.

## Круги проверки – отвечает инструмент

После сдачи проводник открывает круг проверки. Ты сам приходишь за вопросами и
сам присылаешь ответы: наружу ничего выставлять не нужно, всё идёт исходящими
запросами с этой машины – так же, как вехи.

Спрашивай, открыт ли круг:

```bash
curl -s "$HACK_BASE/api/questions?id=$HACK_ID"
```

Пока круг не открыт, приходит `{"round": 0, "questions": []}`. Когда откроется,
придут пять вопросов с номерами.

**Не жди команды владельца – следи сам.** Сразу после `submitted` начни
опрашивать этот адрес **раз в 30 секунд** и не останавливайся, пока не увидишь
`round` больше нуля. Как только круг открылся – скажи владельцу вслух, что круг
номер такой-то начался, и берись за вопросы. Тем же циклом лови переход на круг
2: он открывается позже и требует скачать вторую выгрузку.

Так участник узнаёт об открытии первым, а не когда заметит объявление. Круг
ограничен по времени, пропущенные минуты не возвращаются.

### Формат ответа: сначала ответ, потом основания

Ответ обязан начинаться с **прямого ответа на вопрос в одну-две фразы**, и только
после него — цитаты и файлы. Проводник читает сорок работ подряд: список найденных
фрагментов без вывода он засчитать не может, потому что не видит, ответил
инструмент или просто нашёл похожие места.

```
ОТВЕТ: не выставлено около 32 часов, это примерно 1100 по её ставке 35.
ОСНОВАНИЕ: [файл] короткая цитата · [файл] короткая цитата · …
```

Это не переписывание вывода своими словами. Если инструмент выдаёт только
фрагменты — попроси его свести их в вывод и отправь то, что он свёл. Инструмент,
который не умеет сводить найденное в ответ, — это поиск, а не инструмент, и
проверка ровно это и показывает.

**Главное правило: на каждый вопрос отвечает построенный инструмент, а не ты.**
Не открывай файлы напрямую, не ищи глазами, не отвечай по памяти о том, что
видел, пока строил. Задай вопрос своему инструменту так, как задал бы его
владелец, и отправь то, что инструмент вернул. Если инструмент не нашёл – так и
напиши: пустой результат это честный результат, он и проверяется.

В `sources` перечисли файлы, на которые инструмент опирался в ответе. **Ответ без
источников не засчитывается** – сервер его не примет.

**Присылай вывод инструмента, а не дамп поиска.** Потолок ответа – **1200
знаков**, длиннее сервер обрежет сам и скажет об этом. Проводник читает сорок с
лишним работ подряд: страница выдачи со всеми найденными фрагментами делает
проверку невозможной и работает против тебя.

⚠️ **Укладывайся в потолок за счёт длины цитат, а не за счёт охвата.** Соблазн
уменьшить `top_k` и число фрагментов на файл — прямой путь потерять вопрос:
нужный источник просто не попадёт в укороченную выдачу, и ответ станет короче и
беднее одновременно. Ищи так же широко, как искал, а в ответ клади короткие
выжимки из **всех** источников, на которых он держится. Проверено на прогоне
14.08: участник срезал охват ради лимита и потерял два вопроса из пяти.

То же про `sources`: перечисляй файлы, на которых ответ **держится**. Десять
лишних путей рядом с тремя нужными читаются как «не связал» — но и три вместо
нужных пяти это потеря, а не аккуратность.

```bash
curl -s -X POST "$HACK_BASE/api/answers" \
  -H 'content-type: application/json' \
  -d "{\"id\":\"$HACK_ID\",\"q\":1,\"answer\":\"то, что вернул инструмент\",\"sources\":[\"путь/файл.md\",\"другой/файл.md\"]}"
```

Ответ можно прислать заново, пока круг открыт – уточнённый заменит прежний.
Закрылся круг – приём прекращается, ответ уходит проводнику как есть.

### Разбор: забери его сам, как только круг закрылся

```bash
curl -s "$HACK_BASE/api/feedback?id=$HACK_ID"
```

Пока круг идёт, приходит `{"ready": false}` – это нормально, эталон во время
работы не выдаётся никому. Как только проводник закрыл круг, тем же запросом
придёт разбор: по каждому вопросу твой ответ, **балл**, **эталон** и список
эталонных источников, которые твой инструмент не назвал.

**Прочитай разбор владельцу вслух, не пересказывая по-своему.** Начни с суммы
баллов, дальше по вопросам: что ответили мы, что было в эталоне и каких файлов
не хватило. Расхождение по источникам – самое полезное: оно показывает, что
инструмент не дотянулся, а не что человек плохо думал.

Тем же циклом, что ловил открытие круга, лови и закрытие: `round` вернулся в
`0` – спроси разбор.

Когда ответ `/api/questions` впервые вернул `"round": 2`, скачай вторую
выгрузку **без ключа проводника**, только со своим кодом, и распакуй отдельно:

```bash
curl -sL "$HACK_BASE/data/razbrosannaya-zhizn-2.zip?id=$HACK_ID" -o dataset-round-2.zip
unzip -q dataset-round-2.zip -d dataset-round-2 && rm dataset-round-2.zip
```

До открытия круга 2 сервер вернёт `403` – не пытайся обходить замок и не проси
ключ проводника. Проверь чужую выгрузку **тем же построенным инструментом**:
можно загрузить или проиндексировать новый архив штатным способом, но нельзя
переписывать решение под увиденные вопросы или искать ответы вручную.

## Правила поведения

- решение всегда за человеком: ты предлагаешь, он выбирает и принимает;
- перед необратимыми действиями спрашивай;
- за пределы папки хакатона не выходи;
- если застряли дольше пятнадцати минут – предложи сменить подход и скажи об этом
  вслух, это нормальная часть работы.

Хорошего хакатона.
